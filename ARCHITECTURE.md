# Lock In — Architecture

Native macOS menu bar app (Swift 5 language mode, SwiftUI + AppKit, macOS 14+). Not sandboxed
(the Accessibility API does not work in the sandbox). Hardened runtime with the Apple Events entitlement.
`LSUIElement = YES`: no Dock icon except while the main window is open.

Project is generated by XcodeGen: edit `project.yml`, run `xcodegen generate`. New `.swift` files under
`LockIn/` are picked up automatically after regenerating.

```
LockIn/
  App/          LockInApp.swift (MenuBarExtra scene + AppDelegate), AppModel.swift (composition root)
  Core/         Foundation-only code, ALSO compiled into the test target (no AppKit/SwiftUI here!)
                Models.swift, StudySpaceMatcher.swift, SessionEngine.swift
  Persistence/  AppSettings (UserDefaults), Storage.swift (JSON in ~/Library/Application Support/Lock In/)
  Monitoring/   ActivityMonitor, PermissionsManager, SupportedBrowsers, SpaceCatalog, StudySpaceLauncher
  Alerts/       AlertManager (+ overlay panel, notifications, sound)
  UI/           Theme, menu bar panel + label, main window (Overview / Study Spaces / History / Settings), onboarding
LockInTests/    Swift Testing tests. Test target compiles LockIn/Core/*.swift directly (no host app, no `import LockIn`).
```

## Data flow

```
NSWorkspace / AXObserver / AppleScript ──► ActivityMonitor ──onSnapshot──► AppModel
                                                                            │ StudySpaceMatcher.match(snapshot, enabledSpaces)
                                                                            ▼
                                                                   SessionEngine.ingest(snapshot, matched:)
                                                                            │ onAlert / onDistractionEnded / onSessionEnded
                                                                            ▼
                                                     AlertManager.present / dismiss      SessionStore.append
```

`AppModel.shared` owns everything and is injected into SwiftUI via `.environment(model)`.
UI must call `AppModel` methods (`startSession`, `pauseSession`, `resumeSession`, `togglePause`,
`takeBreak`, `stopSession`, `addSpace`, `updateSpace`, `removeSpace`, `setSpaceEnabled`, `openMainWindow`,
`completeOnboarding`) rather than mutating stores/engine directly. `model.now` ticks at 1 Hz during a session.

## Detection rules (the contract between Monitoring, Matcher, Engine)

* Frontmost app: `NSWorkspace.shared.frontmostApplication` + `didActivateApplicationNotification`. No permission.
* Focused window title / minimized state: Accessibility API (`AXUIElementCreateApplication(pid)` →
  `kAXFocusedWindowAttribute` → `kAXTitleAttribute`, `kAXMinimizedAttribute`). Requires Accessibility.
  Event-driven via `AXObserver` on the frontmost app (focused window changed, title changed, window
  miniaturized/deminiaturized, app hidden/shown, window created/destroyed), plus a fallback poll every 3 s
  (timer tolerance ≥ 1 s) while running. No polling when no session is running.
* Browser tab URL: AppleScript (Apple Events) against the frontmost browser only, on a background serial
  queue, with `with timeout of 2 seconds`. Safari: `URL of current tab of front window`. Chromium family
  (Chrome, Arc, Brave, Edge, Vivaldi, Opera, Chromium, Chrome Canary/Beta, Orion? — check): `URL of active tab of front window`.
  Firefox/Zen: no AppleScript → URL nil, fallback to window title keyword. Only the active tab URL is read.
* Lock In itself frontmost → `isOwnApp = true` → engine keeps its current state (neutral).
* Screen lock (`com.apple.screenIsLocked/Unlocked` distributed notifications), sleep/wake, screens sleep/wake,
  fast user switching → `onAwayStateChanged(true/false)` → engine pauses with reason `.away`.

### Matching (`StudySpaceMatcher.matches`)
* `.app`: `snapshot.bundleID == space.bundleID` AND (window info unavailable OR `hasVisibleWindow`).
* `.window`: same bundle AND visible window AND title contains `titleContains` (case/diacritic-insensitive).
  If window info is unavailable (no Accessibility) degrade to an app-level match.
* `.website`: snapshot is a browser (and `space.bundleID` is nil or equals the browser) AND visible window AND
  - URL known: `urlMatches(url, pattern)`: normalize both (lowercase, strip scheme, `www.`, query, fragment,
    trailing `/`). Pattern without `/`: host == pattern or host ends with "." + pattern. Pattern with `/`:
    host part matches as above AND url path has the pattern's path as a prefix (on a path-segment boundary or not — prefix is fine).
  - URL unknown: match only if `titleContains` is non-empty and window title contains it.
  `about:blank`, new-tab pages etc. never match.

### Engine semantics (`SessionEngine`)
* Time is computed from timestamps (`now()`), never by counting ticks. Accumulators + current segment start.
* `start`: status = studying if matched else distracted (distraction timer starts immediately).
* Switching between study spaces never touches the distraction timer.
* Leaving all spaces → status distracted, `distractionStartedAt = now`. Returning → studying, timer reset,
  episode recorded as `DistractionEvent` (counted in `distractionCount` only if ≥ 15 s), `onDistractionEnded()`.
* Threshold: when `now - distractionStartedAt ≥ distractionThreshold` → `onAlert(context)` once; then again
  every `repeatInterval` (if non-nil) in the same episode. `alertCount` increments per alert. The engine
  schedules a one-shot `Timer` at the next deadline when `schedulesTimers` is true; `tick()` also checks.
* Pause (manual / break / away): accrues paused time only; ends any distraction episode (calls
  `onDistractionEnded`). While paused, `ingest` still records `lastSnapshot`/last match but accrues nothing.
  `resume()` uses the last ingested match to choose studying/distracted; distraction timer starts fresh.
* Break: `pause(for:)` sets `.onBreak(until:)`; auto-resumes at expiry (timer + `tick()`), fires `onBreakEnded`.
* `systemReturned()` resumes only if the pause reason was `.away`. A break that expired while away → resume.
* Ingest when `status == .studying` and matched space changes → update `currentSpace`, `lastStudySpace`,
  and per-space focused time (`spaceBreakdown` keyed by space name).
* `stop()` closes all open segments at `now()`, builds the record, fires `onSessionEnded`, resets to idle.

## Privacy
Only the frontmost app, its focused window title and the active tab URL are read, only during a session,
and only to compare against the user's study spaces. Persisted data: study spaces, settings, session totals,
and the *app name* of each distraction. Configured URL patterns and title keywords are stored as study-space rules; observed URLs, titles, and keystrokes are not stored. Nothing leaves the Mac.

## Windows port

`Windows/LockIn.Windows` is a separate .NET 10 Windows Forms app. It uses `GetForegroundWindow`,
`GetWindowThreadProcessId`, and `GetWindowText` once per second during active sessions. Own-process
windows are neutral. Idle sessions do not poll; the explicit picker enumerates open process windows.
Rules match process names and optional title substrings, with no URL-reading permission or browser integration.

`Windows/LockIn.Core` contains matching models and a timestamp-based session engine, independent of
WinForms/Win32. `Windows/LockIn.Core.Tests` is an executable regression suite runnable on all .NET 10
platforms. The UI marshals lock/unlock and suspend/resume events to the UI thread. Manual pauses
survive unlock; expired breaks wait until the user returns. Data is written through a temporary file
and replaced atomically in `%LOCALAPPDATA%/Lock In/`; an active-session snapshot is saved every 30 seconds.
The next launch recovers the last checkpoint as an ended session, without counting app downtime.
